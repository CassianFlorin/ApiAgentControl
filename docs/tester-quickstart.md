# 给测试者：先读这一页

你收到的是 ApiAgentControl 的 TestFlight 测试版。它让你电脑上的 Codex 会话
（Desktop / CLI / VSCode 插件）能在 iPhone 上查看和控制——审批卡住的命令、
回复 agent 的提问，不用跑回电脑前。

**这个 app 没有服务器。** 没有账号、没有官方中继，后台完全跑在你自己的机器上。
装完 app 还不能用，得先在电脑上把后台跑起来——大约十分钟。

## 开始之前，确认三件事

1. **一台能长期开着不休眠的 Mac。** 这是硬前提。后台进程要在你不在电脑前的时候
   持续工作，Mac 一睡，手机端就失联了。
2. **装了 Node 20 以上**（终端跑 `node --version` 看看）。
3. **装了 Codex**（`codex --version` 能出版本号），并且你平时就在用它。

三条缺一条，现在还跑不起来。

## 先说清楚：推送收不到

**这个测试版不会给你发通知。** 不是 bug，也不是没做完。

推送凭证按 Apple 开发者团队 + Bundle ID 锁死，只有 app 的签名者能签发。你自建的
后台没有、也拿不到这份凭证，所以推不过来。app 里能看见这个状态：
设置页 →「通知」会显示橙色的「电脑端未配置推送」。

**这意味着**：app 在前台时一切实时正常；但退到后台之后，agent 卡住了不会有任何
提醒，得你自己想起来打开看。

想要推送只有一条路：自己从源码构建（需要 Apple 开发者账号），换成自己的 Bundle ID
和自己的推送密钥。步骤见
[部署教程 · 推送通知的边界](deployment-guide.md#推送通知的边界重要)。

## 跑起来

最快的路子（不需要服务器、不需要域名）：

```bash
brew install cloudflared qrencode
git clone https://github.com/CassianFlorin/ApiAgentControl.git && cd ApiAgentControl
scripts/start.sh
```

脚本会把中继、后台进程、公网隧道依次拉起来，最后打印一条配对命令。把它跑一遍，
终端会直接画出二维码，手机扫码即完成配对。

> [!WARNING]
> 这条路子的公网域名**每次重启都会变**，而地址嵌在配对串里——隧道一重启就得
> 重新配对一次。适合先跑通看看。想长期用，把中继放到自己的 VPS 上（一台最便宜的
> 机器就够），配对一次管到底：见[部署教程 · 方案 B](deployment-guide.md#方案-bvps-固定中继长期使用推荐)。

完整步骤、验收方法和排查表都在 [部署教程](deployment-guide.md)。

## 以后怎么更新

两边分开更新，互不等待，版本之间保持兼容，已配对的手机**不用重新配对**：

- **App**：TestFlight 出新版会给你推通知，默认自动更新，不用做什么。
- **电脑端**：在仓库目录里拉最新代码，再把后台重启一遍：

```bash
git pull
```

方案 A 重跑 `scripts/start.sh` 即可；方案 B（launchd）用
`launchctl kickstart -k gui/$(id -u)/com.apiagentcontrol.daemon`。
不重启的话跑的还是旧进程，拉了代码也不生效。

## 两条安全提醒

- **配对时的 `control` 档位等同一个远程 shell**——手机能让 Codex 在你电脑上执行
  任意命令。给自己的手机没问题，但要清楚这意味着什么。不放心可以先配
  `--pair-scope read`（只看不动），随时能再配一个高权限的。
- **配对串（`apiagentcontrol://pair?d=...`）是完整凭证**，包含访问令牌和中继地址。
  拿到它就等于拿到你电脑的访问权。**别截图发群里。**

会话内容本身全程端到端加密，中继和中间的任何节点只看得到密文。

先翻[部署教程](deployment-guide.md)最后的「排查速查」，八成的情况在表里。

```bash
tail -30 ~/.codex-watchd/daemon.log
```

以及手机上设置页的截图。日志里默认不含任何会话正文，可以放心发。
